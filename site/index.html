The terminal coding agent for your local LLM.

koda talks to anything speaking the OpenAI chat-completions API — Ollama, LM Studio, llama.cpp, MLX, vLLM. It reads and edits your code, runs commands, and shows you a diff before it changes anything.

Everything, in the terminal

A full agent that never leaves your shell

File tools run in-process, so they are fast and cannot be talked into doing something sh would. Every capability below is real and shipping.

Local-LLM native

Point it at any OpenAI-compatible server. A text-block tool protocol falls back automatically when a server rejects native tools, so small models still work.

Plan · Execute · Vibe modes

PLAN reads and thinks (no writes). EXEC edits with approval. VIBE writes a spec, does the work, then verifies the result against it. Cycle with ctrl+p.

Tiered auto-approve

Three autonomy tiers cycled live with /auto: ask prompts every time, auto-write approves writes only, full-auto approves everything (shown in red).

Web control center

A localhost page that traces every turn end to end — model calls, tool calls and compaction as a waterfall, with the exact request, raw response and reasoning behind each step. Prompt Δ shows what compaction dropped. The same page changes model, mode, autonomy, toggles, memory and learned rules in the running session.

Code graph

On open, koda scans the project into a symbol graph — definitions, references, imports. The model asks overview, symbol or file instead of grepping.

Durable memory

Facts and command outcomes persist in .koda/memory.md — plain markdown you can read, edit or delete. Next session starts knowing your test runner.

Sessions: resume · search · fork

Conversations save to .koda/sessions as JSONL. Reopen with /resume, find one with /search, or branch a copy with /fork.

Subagents & orchestration

delegate runs a child agent with its own context and read-only tools — only its report reaches your transcript. /orc splits a task across role agents, then integrates and verifies.

Web search

Off by default. Toggle with /websearch. Uses your private SearXNG when searx_url is set, otherwise falls back to DuckDuckGo — no setup.

Image / vision input

Mention an image like any file — @screenshot.png — and koda attaches it for a vision-capable model (png, jpg, gif, webp). Non-image mentions stay as readable paths.

Live themes

/theme shows a swatch of every palette: neon (default), dark, ansi, catppuccin-mocha, tokyo-night, gruvbox-dark, nord, dracula, rose-pine, solarized-light, mono. NO_COLOR forces mono.

Skills & custom tools

Markdown skills load only when relevant, so the prompt stays short. Add a role: field and a skill becomes a specialised subagent. koda skills --init writes an example.

Settings overlay

Press /settings for an interactive page covering every config option — model, modes, autonomy, codegraph, memory, sessions, themes and more, without touching a file.

Install

One command per platform

koda builds from source with Rust 1.82+ (brew install rust or rustup). The installer builds the release binary and drops it on your PATH — no sudo for the per-user install.

one-liner · macOS 
$ curl -fsSL https://raw.githubusercontent.com/simpletoolsindia/koda/master/install.sh | bash

Installs to ~/.local/bin. Run in a terminal from a clone for the interactive menu (install / system-wide / update / uninstall). System-wide: PREFIX=/usr/local ./install.sh.

one-liner · Linux 
$ curl -fsSL https://raw.githubusercontent.com/simpletoolsindia/koda/master/install.sh | bash

Same installer as macOS. Drops the binary in ~/.local/bin; if that is not on your PATH the script prints the one line to add.

PowerShell · Windows 
PS> irm https://raw.githubusercontent.com/simpletoolsindia/koda/master/install.ps1 | iex

Installs to %LOCALAPPDATA%\koda\bin. Override with -Prefix. Requires Rust/cargo (rustup.rs).

from source (any platform) 
$ git clone https://github.com/simpletoolsindia/koda.git && cd koda
$ cargo build --release
$ cp target/release/koda ~/.local/bin/   # or /usr/local/bin
Then point it at a model:
# Ollama
ollama pull qwen2.5-coder:14b
koda -u http://localhost:11434/v1 -m qwen2.5-coder:14b
Model choice matters most. Tool calling makes an agent work, and small models are bad at it. On a 32–64 GB Mac, in rough order: Qwen2.5-Coder 14B/32B, Devstral Small, GLM-4 9B. Give it at least 16k context — agent conversations fill up fast.

Configuration & setup

Sensible defaults, everything tunable

Config lives in ~/.config/koda/config.toml, overridden by a project koda.toml, then environment (KODA_BASE_URL, KODA_MODEL, KODA_API_KEY), then CLI flags.

/setup flow

  1. 1. Run koda and press /setup.
  2. 2. Type your endpoint URL — koda fetches the model list from it.
  3. 3. Pick a model and enter an API key (use local for local servers).
  4. 4. koda writes your config file for you. Done.

koda also reads AGENTS.md, CLAUDE.md or .koda.md from the workspace root as extra instructions.

Tools & approval

Read tools run free; writes and commands are gated.

  • read_file · list_dir · find_files · search — no approval
  • codegraph · skill · todo · remember — no approval
  • delegate · web_search · ask_user — no approval
  • write_file · edit_file — asks, shows a diff first
  • run_command — asks (builds, tests, git)

Autonomy tiers

Cycle live with /auto or set in /settings.

ASKPrompts before every write and command. Default.
AUTO-WRITEAuto-approves writes; still asks before commands.
FULL-AUTOApproves everything. Shown in red in the status bar.

Extend

Skills, roles & custom tools

A skill is instructions loaded only when relevant — the prompt carries one line per skill, the body arrives when the task matches. Add a role: field and that skill becomes a specialised subagent the main agent can delegate to.

  • ▹ Read from ~/.config/koda/skills/ (yours) and <project>/.koda/skills/ (the repo's — commit them).
  • ▹ A project skill overrides a personal one of the same name.
  • ▹ An unused skill costs about fifteen tokens.
  • ▹ koda skills --init writes a commented example and a dev role.
.koda/skills/qa-agent.md 
---
name: qa-agent
role: qa
when: Testing a change end to end
---
Run the suite, report failures with the
exact command and output.
/orc <task> turns koda into an orchestrator: it decomposes the task, writes a brief for each part, hands each to the right role agent, then integrates and verifies the results.
