## What it does

<CardGrid>
  <Card title="Runs on your hardware" icon="laptop">
    Your code is read by a model on your machine. Nothing is uploaded, no account, no
    metering. Cloud endpoints work too — that is your choice, not the default.
  </Card>
  <Card title="Asks before it acts" icon="approve-check">
    Every write shows a unified diff first. Every command asks. `PLAN` mode removes the
    write tools entirely, so nothing on disk can change while you are still thinking.
  </Card>
  <Card title="Runs a real debugger" icon="seti:powershell">
    The `debug` tool drives your language's actual debug adapter — breakpoints,
    stepping, variables, logpoints. The model reads state instead of guessing at it.
  </Card>
  <Card title="Knows where things live" icon="seti:folder">
    A symbol graph of the whole project is built on open, so the model asks where
    `apply_discount` is defined rather than grepping for it.
  </Card>
  <Card title="Survives a small context" icon="seti:config">
    An 8k window fills up fast. koda supersedes stale reads, squeezes what is left on a
    ladder, and only then drops — never the opening request.
  </Card>
  <Card title="Remembers between sessions" icon="seti:notebook">
    Facts, procedures and style rules land as plain markdown in your project you can
    read, edit, commit or delete. Nothing is inferred behind your back.
  </Card>
</CardGrid>
